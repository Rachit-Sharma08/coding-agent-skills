### Check the Composition

When a composition does not render, the Render Manager’s Status field within the render log says so. A few of the things that might cause this include the following:

- No Render Nodes Could Be Found: Over on the Preferences Network tab, confirm that at least one Render node is present, running, and turned on. Should every Render node read as Offline while they aren’t, inspect the network.
- The Composition Could Not Be Loaded: Certain Render nodes might be unable to load a composition even though others manage it. The reason could be that the Render node failed to locate the composition (verify that the composition’s path name is valid for that Render node), or that the composition relies on plugins the Render node doesn’t recognize.
- The Render Nodes Stop Responding: When a network link drops, or a Render node goes offline for whatever reason, that Render node is dropped from the active list and its frames get reassigned. Once no further Render nodes remain, the composition fails after a brief pause (which you can configure in network preferences). Should that occur, scan the render log for hints about which Render nodes failed and the reasons why.
- The Render Nodes Failed to Render a Frame: On occasion a Render node simply can’t render a given frame. Perhaps the Render node was unable to locate every source frame it required, or the disk it wrote to filled up, or any other situation in which Fusion would ordinarily be unable to render a frame. When this occurs, the Render Manager tries to hand that failed frame off to another Render node. If not one Render node can render the frame, the render fails. Render that frame by hand on a single machine and watch what occurs.
- Check the Render Nodes: The Render Manager in Fusion builds in several techniques to safeguard the dependability of network renders. From time to time the Render Manager dispatches signals known as Heartbeats, fired off at steady intervals, in order to catch network or machine failures. Should that happen, a failed Render node’s pending frames are handed to other Render nodes wherever that’s possible. Occasionally a Render node fails in a manner where the heartbeat keeps going even though the Render node has stopped processing. When a Render node has failed (though the Render Master may not have noticed) and you’d rather not sit through the Frame Timeout, just restart whichever Fusion workstation or Fusion Render Node has hung. Doing so kicks off the heartbeat check, reassigns the frames that Render node had been handling, and the render ought to carry on. Heartbeats can also fail when the machine doing the render leans extremely hard on the Swap file, or burns an unusual amount of time waiting on images to arrive across a severely lagging network. The fix is to give the Render node additional RAM, tune that node’s memory settings, or boost the network bandwidth.
- Check the Network: From the Render Master, open the Network tab of the Preferences dialog box and press Scan. When a Render node isn’t shown as running, the Render Master can’t reach it for network rendering. Otherwise, open a command prompt and ping the Render nodes by hand. If those remote systems stay silent while powered on and operating, the network isn’t working and warrants closer inspection.
