### ACESTransform [ATr]

### The ACES Transform node

### ACES Transform Node Introduction

A straightforward node that lets you run color transforms by way of the ACES Input Device Transform and ACES Output Device Transform parameters.

### Inputs

There are two inputs on the ACES Transform node, namely the input plus the effect mask. Input: The orange input carries the main 2D image used for the auto gain. Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. Wiring a mask here confines the change to only the pixels falling inside that mask. The effect mask gets applied once the tool itself has finished processing.

Much like numerous other 2D image-processing nodes, the ACES Transform node takes in a 2D image, for instance a Loader node or the MediaIn1 pictured below. From the output, the node tree carries on by linking into a further 2D image-processing node or a Merge node.

### Inspector

### ACES Transform controls

### Controls Tab

Only the handful of primary controls required to carry out the ACES transform on the input live in the Controls tab. ACES Version Picks which release of ACES you would like to apply. Input Transform Through this menu you select which IDT (Input Device Transform) handles the image. Generally you'd choose here the camera used to capture your footage. Output Transform From this menu you settle on an ODT (Output Device Transform) that converts the image data into the color space of your exported timeline. Gamut Compress Type Here you decide which variety of ACES Gamut compression the node applies. Either choice can stop strongly saturated, monochromatic emitters (LEDs, neon signs, tail lights, etc.) from pushing past and clipping the gamut.

### Chromatic Adaptation [CrA]

### The Chromatic Adaptation node

### Chromatic Adaptation Node Introduction

A straightforward node that lets you accurately convert an image originally lit or handled under one particular color temperature into a different color temperature of your choosing. Such a conversion shifts how every color in the picture appears to human vision exactly as a fresh illuminant would, regardless of whether that illuminant is a light in the recorded environment or the color temperature of a screen the picture is viewed on. The node comes in handy for carrying out targeted color temperature conversions within color management workflows, or for establishing precise color temperature tweaks.

### Inputs

There are two inputs on the Chromatic Adaptation node, namely the input plus the effect mask. Input: The orange input carries the main 2D image used for the auto gain. Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. Wiring a mask here confines the change to only the pixels falling inside that mask. The effect mask gets applied once the tool itself has finished processing.

### Inspector

### ACES Transform controls

### Controls Tab

Only the primary controls required for tuning the Chromatic Adaptation parameters live in the Controls tab. Method The Method pop-up menu offers a range of distinct transform methods you can select, with CAT02 as the default. Every choice within the Method pop-up menu draws on separate measurement datasets to build individual CAT matrixes that steer the conversion. Consequently, each method emphasizes differing levels of precision across different groups of colors. As an illustration:

- CAT02 carries a non-linear element that corrects the tendency of very saturated blues to shift toward purple, a common shortcoming of competing methods. Across the broadest array of measured data sets it typically delivers the strongest result, and it performs best with emissive sources (displays) and dim viewing environments.
- Bradford Linear is another widely adopted method, though one where extremely saturated blues will shift toward purple over the course of the transform. It does a good job alike with emissive sources set in dim surroundings and with reflective sources (theater screens) placed in darkened ones.
- Von Kries ranks among the oldest methods still widely used, even if it too is one where extremely saturated blues shift toward purple over the transform. This method, along with every other one, is on hand whenever you must align with work produced in a separate image processing application.

NOTE: Keep in mind that each method on the list will reproduce neutral colors flawlessly; the sole distinctions concern the way varying bands of saturated color get transformed.

Source/Target Illuminant This conversion is governed via pop-up menus that establish the Illuminant Type for the source (usually whatever color temperature the camera was configured to) along with that of the target you intend to convert the picture into. Within either set of controls, you may select a Standard Illuminant from a list, dial in a Color Temperature with a slider, or supply CIE 1931 xy coordinate values. The conversion of the image is exceptionally accurate, since the picture first goes from the Timeline Color Space across to XYZ, after which it is converted to align with the LMS (long, medium, short) color space that emulates how the eye's cones respond to colors illuminated by various illuminants.

Current Color Space and Gamma The node likewise factors in the clip's present color space and gamma, both of which default to whatever the current timeline uses. Should you want to alter these settings, the Color Space and Gamma menus let you do that.
